# Local Jekyll preview

This branch adds the minimum needed to render the ML curriculum locally with
Jekyll, matching the parent `aet-cs.github.io` site's theme and plugins.

## One-time setup

On macOS (e.g. M4 MacBook Pro), system Ruby is too old for current Jekyll.
Install a modern Ruby:

```bash
brew install ruby
```

After install, follow Homebrew's instructions to add the keg-only ruby to your
PATH (look for the "If you need to have ruby first in your PATH..." line in the
`brew install` output). Verify:

```bash
ruby -v    # should report 3.x
gem -v
```

Then install the gem dependencies:

```bash
cd ML-curriculum
bundle install
```

This creates a `Gemfile.lock` (currently in `.gitignore`; flip that if you want
to commit it for reproducibility).

## Running the preview

```bash
bundle exec jekyll serve
```

The site renders at <http://localhost:4000>. With `--livereload` the page
auto-refreshes on edits:

```bash
bundle exec jekyll serve --livereload
```

To rebuild only (no server):

```bash
bundle exec jekyll build
```

To regenerate notebook HTML companions and link metadata locally:

```bash
python3 scripts/export_notebooks.py
python3 scripts/generate_notebook_metadata.py
```

That metadata command also regenerates the workspace snippet file for local
unit-page notebook choices at `.vscode/generated-notebook-local-choices.code-snippets`.

To enable the repo-managed pre-commit hook that keeps local notebook artifacts
in sync for staged notebook changes:

```bash
./scripts/install_git_hooks.sh
```

Output goes to `_site/` (gitignored).

## What's where

- `_config.yml` — site configuration, adapted from the parent site
- `_data/navigation.yml` — the "ml" sidebar referenced by `calendar.md`
  (`sidebar: nav: "ml"`). Edit this to control the left navigation
- `Gemfile` — gem dependencies (Jekyll 4.3, Minimal Mistakes, plugins)
- `Gemfile.lock` — generated by `bundle install`, gitignored

## Notes

- The `.ipynb` files are **not** rendered as pages by Jekyll. They're served
  as static files (raw JSON). Student-facing notebook pages come from generated
  `.html` companions produced by `scripts/export_notebooks.py`, and the shared
  notebook link include reads `_data/notebooks.json` generated by
  `scripts/generate_notebook_metadata.py`.
- Generated notebook `.html` files and `_data/notebooks.json` are treated as
  local/CI build artifacts, not committed source.
- Use `{% include nb.html file="Decision_Tree_Student.ipynb" %}` inside
  markdown pages to render the standard notebook actions.
- For notebook landing pages that live inside a unit folder, use
  `{% include nb.html local="Decision_Tree_Student" %}` to resolve notebooks
  relative to that page's folder.
- For faster local authoring, generated snippets use a single searchable global
  notebook-choice trigger: `nbloc` for a local include and `nblocl` for the
  labeled variant. If you want a raw free-typing local include instead, use
  `nblocraw` or `nbloclraw`.
- GitHub Actions regenerates notebook artifacts, builds Jekyll, and deploys the
  resulting `_site` to GitHub Pages on pushes to `main`.
- `_orphans/` (under `notebooks/`) starts with an underscore, so Jekyll
  ignores it by default. Files there won't appear in the rendered site. If you
  want them browsable, rename the directory.
- The `scripts/` directory is excluded in `_config.yml` so reorganization
  helper scripts don't end up in the rendered output.
- The `drafts/Unit4_Deep_Dive.md` (teacher-facing annotation) is excluded too.
  `drafts/Unit4_Student_Scaffolding.md` and `drafts/README.md` will render.

## Production differences

The parent site sets:

```yaml
url: https://aet-cs.github.io/
baseurl: /white/2025/ML/   # or similar
```

This local-preview config uses empty `url`/`baseurl` so everything serves at
the root. If you ever want to test the production path locally, copy your
parent site's `_config.yml` values into a `_config.production.yml` and run
with `--config _config.yml,_config.production.yml`.
