**Course:** Machine‑Learning – Anomaly Detection & Imbalanced Data

### 2. SMOTE – Synthetic Minority Over‑sampling Technique

#### 2.1 What SMOTE Does

1. **Identify a minority (positive) point** – e.g. a known fraudulent transaction.
2. **Find its *k* nearest minority neighbours** (default = 5).
3. **Randomly pick one neighbour** and draw a line between the two points.
4. **Sample a point on that line** (by a random interpolation factor ∈ [0,1]).
5. **Add the synthetic point to the training set**.

Repeat until the desired class balance is reached (often a 50/50 split).

> **Key Insight:** SMOTE *creates* new minority examples **inside** the feature space spanned by real minority points, rather than just copying them.

#### 2.2 Correct Workflow

```
1️⃣  Split original data → train / test (e.g. 80/20).
2️⃣  **Apply SMOTE only on the TRAINING data** → balanced_train.
3️⃣  Fit any classifier on balanced_train.
4️⃣  Evaluate on the ORIGINAL TEST set (still imbalanced!).
```

*Never* SMOTE the test set – otherwise the evaluation would be on synthetic data whose true label you do not know.

#### 2.3 Common Pitfalls

| Pitfall                        | Why it’s a problem                                                                                               | Fix                                                                                                          |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| SMOTE on test data             | Inflates performance, creates “fake” positives.                                                                  | Keep test data untouched.                                                                                    |
| Ignoring feature correlation   | SMOTE works in the raw feature space; if features are highly correlated the synthetic points may be unrealistic. | Optionally use **SMOTE‑ENN** or **SMOTE‑Tomek** to clean noisy synthetic samples.                            |
| Over‑balancing → large dataset | Too many synthetic points can make training slow.                                                                | Choose a modest oversampling ratio (e.g., 100 % of minority size) or use **class_weight** on the classifier. |

### 3. Gaussian‑Mixture Models (GMM) for Anomaly Detection

#### 3.1 Intuition

- A **Gaussian mixture** assumes the data is generated by a **weighted sum of multivariate normal distributions** (components).
- In 1‑D you could picture several bell‑shaped curves stacked together.
- In high‑dimensional space each component is a *cluster* (a “blob”) having its own **mean vector** and **covariance matrix**.

```
p(x) = Σ_{c=1}^{C} π_c  · 𝒩(x | μ_c, Σ_c)
π_c ≥ 0,   Σ_c π_c = 1
```

#### 3.2 Why GMMs are Good for Anomaly Detection

1. **Unsupervised on the *normal* class** – you only train on “good” transactions.
2. The model learns the *density* of normal data.
3. **Anomaly score** = –log likelihood under the mixture. Low likelihood → likely anomaly.
4. The score is *continuous* → you can choose any threshold that balances **Recall** (catching fraud) vs **False‑Positive Rate** (inconveniencing customers).

#### 3.3 Typical GMM Anomaly‑Detection Pipeline

```
1️⃣  Split data → train / test (no labels needed for training!).
2️⃣  Train GMM **only on the NORMAL (Class=0)** training rows.
3️⃣  Compute log‑likelihood for every point (train & test).
4️⃣  Choose a threshold τ.  Points with score < τ are flagged as anomalies.
5️⃣  Evaluate against the true labels (only for reporting):  TP, FP, FN, TN → precision, recall, F1, …
```

> **Important:** Do **not** mix the fraudulent class into the GMM training – otherwise the model will *learn* that fraud is “normal”.

#### 3.4 Parameters to Play With

| Parameter                                               | Effect                                                                                                              | Typical range                                              |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `n_components` (number of Gaussians)                    | Controls model flexibility. Too few → under‑fit (high false negatives). Too many → over‑fit (high false positives). | 1 – 10 (use BIC/AIC to select).                            |
| `covariance_type` (`full`, `tied`, `diag`, `spherical`) | Shape of each component’s covariance. `full` is most expressive but slower.                                         | Start with `diag`.                                         |
| `threshold` (or equivalently a *z‑score*)               | Moves the decision line left/right. Higher threshold → catch more fraud but also more false alarms.                 | Sweep over a fine grid (e.g., 0.1 – 10).                   |
| Feature selection                                       | Removing noisy columns (e.g., V3 in the notes) improves density estimation.                                         | Keep only variables with clear separation (e.g., V5, V12). |

### 4. Feature‑Distribution Visualisation

- Plot each feature **separately** for *normal* vs *fraud* rows (kernel‑density estimate or histogram).
- Look for **clear separation** (e.g., V5 may show distinct peaks).
- Features that *overlap heavily* (e.g., V3) can be **dropped** because they add noise to the GMM.

---

### 5. Evaluation & the “Quotient” Metric

The notebooks report a custom **ratio** (let’s call it *Fraud‑Capture‑Efficiency*):

```
ratio = TP / (TP + FP)      # aka precision for the fraud class
```

- **Goal**: maximise the ratio while keeping an acceptable **Recall** (TP / (TP + FN)).
- The baseline in the notebook gave ≈ 4 % – i.e. only 4 % of flagged cases were actually fraud.
- By tweaking `n_components`, the decision threshold, and the selected features you can push this far higher (often > 40 % on the Kaggle data set).

### 6. Quick Summary

| Concept               | What to Remember                                                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **SMOTE**             | Synthetic oversampling *only on training data* → balanced dataset → any classifier works.                                        |
| **GMM**               | Unsupervised density model on normal data → continuous anomaly scores → easy threshold tuning.                                   |
| **Feature‑selection** | Visualise per‑feature distributions; keep those that separate classes.                                                           |
| **Evaluation**        | Use precision, recall, F1, *and* the custom ratio (TP/(TP+FP)).                                                                  |
| **Tuning**            | `n_components`, `covariance_type`, threshold, and selected features are the levers.                                              |
| **Practical tip**     | Start with a simple 2‑D synthetic example, verify SMOTE & GMM behaviours, then move to the real 28‑dimensional credit‑card data. |
